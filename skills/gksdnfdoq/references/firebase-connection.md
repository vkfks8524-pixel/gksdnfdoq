# Firebase 관리 도구 연결 점검

Apps Script 경로에서 사용자가 Firebase 연결 필요 여부를 안내받고 다른 화면에 바로 반영하는 방식을 선택했을 때 읽는다. 버튼 조회만 사용하는 앱에는 이 절차를 추가하지 않는다.

## 무엇을 점검하는가

Firebase CLI는 터미널에서 프로젝트와 서비스를 관리하는 도구이고, Firebase MCP 서버는 AI가 Firebase 관리 도구를 호출할 수 있게 하는 연결이다. 현재 환경에서 쓸 수 있는 기능을 확인해 활용한다. 특정 제품이나 기기에만 존재하는 연결을 전제로 하지 않는다.

다음 상태는 서로 구분한다.

| 단계 | 확인할 내용 |
| --- | --- |
| 관리 도구 사용 가능 | Firebase MCP 도구를 호출할 수 있는지, 또는 터미널에서 Firebase CLI를 실행할 수 있는지 |
| 계정 로그인 | Firebase를 관리할 Google 계정의 인증이 준비되어 있는지 |
| 대상 프로젝트 | 이번 웹앱에 사용할 프로젝트가 정해졌는지, 해당 계정으로 접근 가능한지 |
| 앱 연결 준비 | 선택한 프로젝트의 Realtime Database, 웹 앱 설정, 익명 인증과 보안 규칙이 준비·배포됐는지 |
| 사용자 동작 점검 | 웹앱 연결 후 사용자에게 점검 항목을 제공했는지, 사용자가 어떤 결과를 알려줬는지 |

MCP 도구가 목록에 보이거나 CLI 버전이 출력된다는 이유만으로 로그인·프로젝트 접근·앱 연결이 모두 완료됐다고 판단하지 않는다. 계정에 저장된 로그인 정보가 있다는 것과 특정 프로젝트에 실제로 접근할 수 있다는 것도 구분한다.

## 관리 도구와 로그인 확인

1. 현재 환경에 Firebase 관리 도구가 제공되는지 살핀다. 충분한 기능의 MCP 도구가 있으면 우선 사용한다. `firebase_get_environment` 같은 환경 조회 도구로 현재 작업 폴더, 인증 정보, 활성 프로젝트를 확인한다.
2. MCP가 없거나 필요한 기능을 제공하지 못하면 사용 가능한 터미널의 Firebase CLI를 확인한다. 예를 들어 아래 명령으로 버전과 로그인 정보를 확인할 수 있다. 사용 중인 버전의 도움말과 공식 문서를 함께 참고한다.

   ```text
   npx -y firebase-tools@latest --version
   npx -y firebase-tools@latest login:list
   ```

3. 관리 도구가 없으면 연결 또는 설치가 필요함을 안내한다. 현재 AI 환경이 제공하는 플러그인·MCP 연결 기능이나 CLI 실행 환경 중 적합한 경로를 사용한다. 이미 쓸 수 있는 경로가 있다면 같은 일을 위해 다른 관리 도구를 추가로 설치하게 하지 않는다.
4. 로그인이 안 되어 있거나 만료됐다면 Firebase를 관리할 Google 계정으로 로그인하는 절차를 안내한다. MCP의 로그인 도구 또는 다음 CLI 명령을 사용할 수 있다.

   ```text
   npx -y firebase-tools@latest login
   ```

   로컬 브라우저 연결이 어려운 원격 환경에서는 공식 절차에 따라 `--no-localhost` 옵션을 사용할 수 있다. 실제 로그인·동의는 사용자가 완료하도록 하고, 비밀번호나 저장된 인증 토큰을 채팅으로 요구하지 않는다. 로그인 도구가 인증 링크와 세션 ID를 반환하면 둘 다 보여주고, 브라우저의 세션 ID가 일치하는지 확인하도록 도구 지침에 따라 안내한다.

5. 로그인 후 환경을 다시 조회한다. 필요하면 프로젝트 목록이나 지정된 프로젝트를 읽는 작업으로 실제 접근을 확인한다. 네트워크 오류나 도구 장애를 근거 없이 로그아웃 상태로 단정하지 않는다.

이 Google 계정 로그인은 앱을 만드는 교사의 Firebase 관리 연결이다. 학생에게 Google 계정 로그인을 요구하는 것으로 바꾸지 않는다. 학생의 명렬 기반 로그인과 Firebase 관리 계정의 인증은 별개다.

## 대상 프로젝트: 새 웹앱은 새 프로젝트가 기본

- 새로 개발하는 웹앱에서 Firebase를 선택했다면 이 앱 전용의 새 Firebase 프로젝트를 생성해 시작한다. 관리 도구 연결과 로그인을 확인한 뒤 “새로 만드는 웹앱이므로 이 앱 전용 Firebase 프로젝트를 만들어 연결하겠습니다. 기본 적용 사항이며, 원하시는 구성이 다르면 편하게 말씀해 주세요.”처럼 안내하고 진행한다. 이미 정해진 이 기본값을 다시 승인받거나 기존·신규 프로젝트 선택 질문을 반복하지 않는다.
- 사용자가 기존 Firebase 프로젝트 사용을 명시했다면 그 요청을 우선하고 ID와 작업 폴더의 설정을 대조한다. `.clasp.json`의 Apps Script ID는 Firebase 프로젝트 ID가 아니다.
- 같은 앱의 작업을 이어가는 경우 이미 생성·연결한 Firebase 프로젝트를 재사용한다. 스킬을 다시 불렀거나 연결을 재시도했다는 이유로 프로젝트를 추가 생성하지 않는다.
- `firebase.json`, `.firebaserc` 또는 활성 프로젝트 정보가 있으면 기존 설정을 읽는다. 다른 작업에서 쓰던 활성 프로젝트를 이번 웹앱의 대상으로 자동 선택하지 않는다.
- 새 프로젝트의 이름과 ID는 앱의 이름·목적과 사용 중인 도구의 요구사항에 맞춰 정하고, 생성 결과의 실제 프로젝트 ID를 해당 앱의 작업 기록과 설정에 남긴다. 결과가 불분명하면 생성 여부부터 확인해 중복 생성을 피한다. 생성 권한이나 할당량 문제 등이 있으면 실제 오류와 필요한 조치를 안내하며, 다른 기존 프로젝트로 임의 전환하지 않는다.
- 도구·로그인 연결 점검 자체는 읽기 작업으로 수행하고, 준비된 뒤 위 기본값에 따른 프로젝트 생성·연결을 별도 단계로 진행한다. 규칙 변경은 실제 구현에 필요한 범위가 정해진 뒤 진행한다. 점검을 위해 빈 설정 파일을 만들거나 기존 프로젝트의 설정·규칙을 덮어쓰지 않는다.
- 도구 연결과 로그인은 정상이어도 프로젝트 생성 전일 수 있다. 이 경우 “Firebase 연결 필요”라고 뭉뚱그리지 말고 “계정 연결은 준비됐고, 이제 이 앱 전용 새 프로젝트를 만들 차례입니다”라고 안내한다. 중간 요약에는 “새 프로젝트 사용 — 기본 적용 / 생성 예정”과 실제 생성 완료를 구분해 표시한다.
- 프로젝트 읽기가 성공했다고 규칙 배포 등 모든 쓰기 권한까지 검증됐다고 보고하지 않는다. 권한 오류가 발생하면 실패한 작업과 필요한 접근 범위를 구체적으로 안내한다.

## 준비되지 않았을 때의 안내 예시

상태에 해당하는 안내만 사용하고, 사용자에게 전체 기술 점검표를 한꺼번에 설명하지 않는다.

**관리 도구가 없는 경우**

> 바로 반영 기능을 만들려면 AI가 Firebase를 설정할 수 있도록 관리 도구 연결이 필요해요. 현재 환경에서는 그 연결을 확인하지 못했습니다. 사용 중인 도구에 맞는 Firebase 연결 방법을 안내해드릴게요.

**Google 계정 로그인이 필요한 경우**

> Firebase 관리 도구는 준비되어 있지만, 사용할 Google 계정의 로그인이 필요해요. 안내되는 로그인 절차를 마치면 프로젝트 연결을 이어가겠습니다.

**새 웹앱의 계정 연결은 준비됐고 프로젝트 생성 전인 경우**

> Firebase 관리 도구와 계정 연결은 확인됐어요. 새로 만드는 웹앱이므로 이 앱 전용 Firebase 프로젝트를 만들어 연결하겠습니다. 원하시는 구성이 다르면 편하게 말씀해 주세요.

**선택한 프로젝트에 접근할 수 없는 경우**

> 현재 로그인한 계정으로는 선택한 프로젝트에 접근하지 못했습니다. 해당 프로젝트를 사용할 수 있는 계정인지, 프로젝트 ID가 맞는지 확인이 필요해요.

연결이나 로그인이 막혀도 이미 정리한 앱 기획과 개발 준비는 유지한다. 관련된 Firebase 원격 작업은 준비가 된 뒤 이어가며, 막힌 단계를 완료했다고 보고하지 않는다.

## 연결 후 자동 설정으로 이어갈 때

프로젝트가 준비되면 [Firebase 자동 설정·익명 인증·보안 규칙](firebase-provisioning.md)을 읽고 AI가 실제 설정·코드 연결·규칙 작성·배포를 수행한다. 현재 환경의 MCP 기능을 우선 사용하고, 부족한 부분은 지원되는 CLI로 이어간다. 이미 이 흐름으로 개발을 진행하기로 했으면 기술 설정을 단계마다 다시 승인받지 않는다. 앱 동작 검증은 사용자 체크리스트로 안내한다.

사용자에게는 “Firebase 설정과 익명 인증, 이 앱에 필요한 접근 규칙까지 제가 구성하고 배포하겠습니다. 직접 로그인하셔야 하는 단계가 있으면 안내하고, 완료 후에는 사용하시면서 확인할 점검 항목을 드릴게요.”처럼 설명한다. 도구 연결이나 배포 성공만으로 동기화 테스트가 완료됐다고 보고하지 않는다.
