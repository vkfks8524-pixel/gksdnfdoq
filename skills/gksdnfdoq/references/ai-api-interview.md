# 사용자가 AI 기능을 요청했을 때의 API 안내

사용자가 **만들 도구 안에서 AI 기능을 사용하고 싶다**고 말했을 때만 읽고 적용한다. AI 활용 여부를 모든 사용자에게 묻는 필수 인터뷰 단계로 만들지 않는다.

## 이 흐름을 시작하는 조건

- “학생 글에 AI가 피드백해주면 좋겠어요”, “앱에 AI 챗봇을 넣고 싶어요”, “AI가 문제를 만들어주면 좋겠어요”처럼 사용자가 앱 안의 AI 기능을 먼저 요청하면 시작한다. 이미 의사를 밝혔다면 “AI를 사용하시겠어요?”라고 다시 묻지 않는다.
- “AI로 도구를 만들어줘”처럼 개발을 AI에게 맡기는 말만으로는 앱에 AI 기능을 넣겠다는 뜻으로 해석하지 않는다. 사용자가 말한 AI의 역할이 불명확할 때에만 앱 안에서 어떤 일을 하기를 원하는지 짧게 확인한다.
- AI 기능을 먼저 제안하거나 “AI도 사용해볼까요?”, “API KEY가 있으신가요?”를 선제적으로 질문하지 않는다. 일반적인 퀴즈·요약·피드백 기능을 언급했다는 이유만으로 외부 AI 연동을 자동 확정하지 않는다.
- 만들 도구와 사용 상황을 먼저 파악하는 흐름을 유지한다. 스크립트 ID 요청·클론은 Apps Script 경로에서만 수행한다. 사용자가 처음부터 AI 기능을 말했다면 그 요구를 기억하고 이후 기능 대화에서 재사용한다.

## API와 API KEY를 설명하는 순서

사용자의 실제 앱을 예로 들어 아래 내용을 쉬운 말로 연결해 설명한다. “키가 있어야 합니다” 한 문장으로 끝내거나 기술 용어를 나열하지 않는다. 이미 이해하고 있다고 밝힌 사용자는 아는 설명을 반복하지 않고 필요한 부분만 확인한다.

1. **API의 역할:** API는 도구가 다른 서비스에 일을 요청하고 결과를 받는 연결 창구다. 예를 들어 학생이 ‘피드백 받기’를 누르면 앱이 필요한 글과 요청 내용을 AI 서비스에 보내고, 받은 피드백을 앱 화면에 보여준다. 실제 AI 처리는 연결한 서비스가 수행한다.
2. **API KEY의 역할과 필요성:** 이 스킬에서 기본으로 안내하는 외부 생성형 AI API 연결 방식에는 해당 서비스의 API KEY가 필요하다. 키는 앱이 그 서비스를 이용할 때 제출하는 연결용 열쇠이며, 서비스가 어느 계정·프로젝트의 사용량인지 구분하는 데 쓰인다. 모든 AI 실행 방식이 반드시 키를 쓴다고 일반화하지 않으며, 사용자가 이미 별도의 인증 방식이나 로컬 AI 실행을 지정했다면 그 방식을 확인하며 외부 API와 키를 강요하지 않는다.
3. **일반 채팅 이용과의 차이:** AI 채팅 사이트를 이용하거나 구독하는 것만으로 도구에서 API를 사용할 준비까지 끝났다고 가정하지 않는다. API용 키와 이용 가능 상태를 별도로 확인한다. 서비스마다 무료 이용 범위·사용량 제한·과금 방식이 다를 수 있으며, 구체적인 발급 방법과 현재 요금은 서비스가 정해진 뒤 공식 안내로 확인한다.
4. **키를 전달하는 방법:** 지금은 키 보유 여부와 서비스 이름만 확인한다. 키 문자열을 대화에 붙여 넣도록 요청하지 않는다. 실제 연결 단계에서는 선택한 실행 환경에 맞는 비밀 설정 위치를 안내한다. 웹앱의 공용 키는 서버 측에 보관하고, 배포할 실행 프로그램에는 개발자의 공용 비밀 키를 포함하지 않는다.

학생 글에 AI 피드백을 주고 싶다고 한 경우의 설명 예시:

> 학생이 쓴 글을 보고 AI가 피드백해주는 기능을 원하시는군요. 이 기능은 도구와 AI 서비스를 연결해서 만들 수 있어요. 연결에 필요한 API와 API KEY를 먼저 설명드릴게요.
>
> **API는 도구가 AI에게 일을 부탁하고 답을 받는 창구**라고 생각하시면 돼요. 학생이 ‘피드백 받기’를 누르면 앱이 필요한 글과 요청을 AI 서비스에 보내고, AI가 돌려준 피드백을 화면에 보여주는 흐름입니다. 선생님이나 학생이 매번 AI 채팅창으로 글을 복사해 옮길 필요가 없어져요.
>
> 이 방식으로 연결하려면 **해당 AI 서비스의 API KEY**가 필요해요. 도구가 그 서비스를 사용할 때 내미는 연결용 열쇠 같은 값입니다. 서비스는 이 키를 통해 어느 계정이나 프로젝트에서 사용하는지 구분하고 사용량을 관리합니다.
>
> 평소 AI 채팅 서비스를 이용하거나 구독하고 계셔도, 도구에 연결하는 API 이용은 별도로 준비해야 할 수 있어요. 무료로 사용할 수 있는 범위나 비용도 서비스마다 다르므로, 사용할 서비스를 확인한 뒤 필요한 준비를 차근차근 안내해드릴게요.
>
> **현재 도구 연결에 사용할 수 있는 API KEY가 있으신가요?** 있다면 어느 AI 서비스의 키인지 알려주세요. **키 값 자체는 보내지 않으셔도 됩니다.** ‘있어요 / 아직 없어요 / 있는지 잘 모르겠어요’ 정도로 답해주셔도 좋고, 현재 사용 중인 AI 서비스를 편하게 설명해주셔도 좋아요.

이 예시의 기능·입력·결과는 실제 대화에 맞게 바꾼다. 학생 글 피드백을 모든 앱에 기본 기능으로 추가하지 않는다.

## 답변에 따라 이어가기

- **키가 있음:** 어느 서비스용인지 확인하고, 이미 알려준 서비스는 다시 묻지 않는다. AI가 맡을 일과 입력·결과·실행 버튼을 앱의 흐름으로 구체화한다. 보유했다는 답만으로 키 유효성·잔여 사용량·연결 성공을 확인했다고 보고하지 않는다.
- **키가 없음:** 처음 준비하는 상황임을 받아주고, 사용자가 원하는 기능과 선호 서비스에 맞춰 발급 준비를 안내한다. 특정 업체를 임의로 확정하거나 유료 결제·키 발급을 자동 진행하지 않는다. 사용자가 서비스를 선택하면 현재 공식 발급 화면과 필요한 단계를 쉬운 한국어로 안내한다.
- **잘 모름:** 현재 이용하는 서비스와 API 키를 발급한 적이 있는지 정도로 좁혀 돕는다. 계정 비밀번호·로그인 토큰·키 문자열을 요구하지 않는다. 이미 마련한 키나 다른 인증 방식이 확인되면 중복 발급을 기본으로 요구하지 않는다.
- **나중에 연결:** AI 기능과 키 준비를 후속 항목으로 남긴다. 먼저 만들기로 한 나머지 기능은 진행할 수 있지만, 키가 준비되지 않은 AI 기능을 실제로 연결·완료한 것처럼 표현하지 않는다.

## 이후 구현과 설명서에 연결하기

- AI 키는 Firebase 웹 SDK의 공개 연결 설정과 구분한다. AI 서비스용 비밀 키는 HTML·브라우저 JavaScript·시트·Git·로그·README·초기 설정 응답에 노출하지 않는다. Apps Script에서 연결한다면 별도 스크립트 속성 같은 서버 측 설정에서 읽어 서버가 API를 호출하도록 구성한다. 키 값을 사용자에게 설정하도록 안내할 때에도 대화에 붙여 넣게 하지 않는다.
- 실행 프로그램을 배포할 때 개발자의 공용 비밀 키를 소스·실행 파일·동봉 설정에 넣지 않는다. 사용자가 자기 키를 쓰는 방식이라면 OS 자격 증명 저장소 등 적절한 로컬 비밀 설정을 사용하고, 공용 서비스가 필요하면 승인된 별도 서버 구성을 설계한다. 로컬 프로그램의 설정을 서버 전용 저장소라고 설명하지 않는다.
- 선택한 AI API의 인증·호출 방법·키 제한·사용량 안내는 해당 제공자의 현재 공식 문서로 확인한다. Google 계열 API 키의 역할과 취급 예시는 [공식 키 관리 안내](https://docs.cloud.google.com/docs/authentication/api-keys)와 [키 보호 지침](https://docs.cloud.google.com/docs/authentication/api-keys-best-practices)을 참고할 수 있으며, 다른 제공자에는 해당 제공자의 지침을 적용한다.
- 선택한 제작 경로의 저장·빌드·전달·사용자 점검 방식을 유지한다. AI 키 확인을 명목으로 AI가 실제 생성 요청을 보내 테스트하지 않는다. 앱 README에는 AI 기능이 있는 경우에만 API 설명, 선택한 서비스, 키 설정 위치와 방법, 관련 버튼 사용법, 필요한 준비 사항을 담고 실제 키는 쓰지 않는다.
