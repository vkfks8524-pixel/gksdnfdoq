# 웹앱의 화면 반영 방식으로 실시간 동기화 선택하기

Apps Script 경로에서 한 사용자가 제출·저장·수정한 내용을 다른 화면에서 확인하는 웹앱을 기획할 때 읽는다. 화면 동작과 Firebase 연결 필요 여부를 함께 설명해 사용자가 선택할 수 있게 하고, 그 답에 따라 이 스킬의 Firebase 연동 경로를 선택한다. 다른 제작 방식에 Firebase를 필수 동기화 수단으로 강제하지 않는다.

## 질문할 때 사용할 맥락

이미 인터뷰에서 파악한 앱의 목적, 동작, 데이터, 공유 대상을 사용한다. 사용자가 이미 “제출하면 선생님 화면에 바로 보여주세요”처럼 명확하게 설명했다면 선택을 반복해서 묻지 않고, 이 구성에는 Firebase 설정·연결이 필요함을 포함해 해당 경로를 안내한다. 사용자가 준비 과정의 차이를 듣고 방식을 바꾸면 그 요청을 반영한다.

| 웹앱의 종류 | 학생의 동작과 반영할 데이터 예시 |
| --- | --- |
| 응답 수집 | 학생이 제출한 응답 |
| 문제 풀이 | 학생이 제출한 답안 |
| 수업 중 활동 | 학생이 저장한 활동 기록 |

이 표는 질문을 만드는 재료다. 실제 앱의 표현을 우선하며, 모든 예시를 사용자에게 한꺼번에 나열하지 않는다. 공유 대상이 교사 화면으로 정해졌다면 질문에도 교사 화면만 넣는다. 다른 학생에게 공유하기로 정했다면 해당 학생 화면을 포함한다. 누가 볼지 아직 불분명하면 그 부분만 짧게 확인한다.

혼자 사용하는 앱에서 본인의 버튼 동작 결과가 자기 화면에 나타나는 것만으로 Firebase가 필요한 공유 동작이라고 판단하지 않는다. 화면 간 공유 자체가 없다고 확인된 앱은 그 사실을 기록하고 Firebase 없이 진행한다.

## 질문의 기본 형태

응답 수집 앱에서 교사만 응답을 확인하는 경우의 예다.

> 학생이 응답을 제출하면, 선생님 화면에는 어떤 방식으로 나타나면 좋을까요?
>
> 1. **바로 반영 — Firebase 연결 필요:** 선생님이 새로고침하거나 버튼을 누르지 않아도 새 응답이 바로 나타나요. 이를 위해 Firebase 설정·연결 과정이 필요해요.
> 2. **버튼으로 확인 — Firebase 연결 없이 가능:** 선생님이 ‘응답 불러오기’ 같은 버튼을 눌렀을 때 최신 응답을 가져와요. 별도의 Firebase 연결 없이 사용할 수 있어요.
>
> 혹은 원하시는 반영 방식을 자유롭게 설명해주셔도 좋아요.

문제 풀이 앱이라면 ‘응답’을 ‘제출한 답안’으로, 수업 활동 앱이라면 ‘저장한 활동 기록’으로 바꾸는 등 대화에 맞게 표현한다. 버튼 이름도 예시임을 알 수 있게 제시하고, 최종 앱의 실제 동작에 맞게 정한다.

질문을 다른 앱에 맞춰 바꿀 때에도 각 선택지의 Firebase 연결 필요 여부를 유지한다. 이 스킬에서 사용하는 구성 기준임을 전제로 설명하며, 자동 반영의 편리함만 보여주고 추가 연결 과정을 선택 이후로 미루지 않는다.

학생의 제출·저장 동작과 결과를 보는 사람의 조회 동작을 구분한다. 두 방식 모두 학생이 제출 버튼을 누르는 흐름일 수 있다. 이 질문은 그 이후 다른 화면에 어떻게 반영할지를 정한다. 자동 반영을 선택했다고 학생이 작성 중인 모든 내용을 매 입력마다 보내도록 임의로 확장하지 않는다.

## 답변에 따른 진행

### 다른 화면에 바로 반영하기

- Firebase Realtime Database를 연동하는 경로로 진행한다. Cloud Firestore로 임의 변경하지 않는다.
- “학생이 제출한 응답이 선생님 화면에 바로 반영되도록, 화면 간 데이터를 동기화하는 Firebase를 연결하는 구성으로 진행하겠습니다.”처럼 원하는 동작과 구현 방향을 연결해 안내한다.
- 같은 선택을 “그럼 Firebase를 쓰실까요?”라고 다시 묻지 않는다. 이후 실제 연동에 필요한 설정 절차로 이어간다. 사용자에게는 앱의 동작을 중심으로 설명한다.
- 실제 연동에 앞서 [Firebase 관리 도구 연결 점검](firebase-connection.md)을 읽고 MCP 또는 CLI와 계정 로그인을 확인한다. 새 웹앱은 이 앱 전용의 새 Firebase 프로젝트에서 시작하는 기본값을 안내하고, 관리 연결이 준비되면 생성·연결을 진행한다. 사용자가 지정한 기존 프로젝트나 같은 앱을 위해 이미 만든 프로젝트가 있으면 이를 확인해 재사용한다. 도구 설치, 로그인, 프로젝트 생성·접근 확인을 모두 하나의 연결 완료 상태로 합치지 않는다.
- 이어서 [Firebase 자동 설정·익명 인증·보안 규칙](firebase-provisioning.md)에 따라 AI가 설정과 필요한 배포를 수행한다. 사용자에게 SDK 설정 복사, `firebase` 탭 작성, 익명 인증 활성화나 규칙 붙여 넣기를 수동 과제로 넘기지 않는다. 누가 무엇을 보고 수정하는지에 관한 미정 사항은 앱의 사용 방식으로 질문하고, 규칙 코드나 경로 설계를 교사에게 요구하지 않는다.
- 어떤 행동 뒤에, 어떤 데이터가, 어떤 화면에 반영되는지 기록한다. 이미 설명된 내용을 반복해서 질문하지 않는다.
- Firebase 공식 실시간 이벤트 리스너로 구성한다. 시트나 서버를 반복 조회해 실시간처럼 보이게 하는 폴링은 사용하지 않는다.
- [데이터 저장 기본값](data-storage-and-actions.md)을 적용한다. RTDB는 실시간 반영에 필요한 현재 상태·임시 표시 데이터만 다루고, 보관할 최종 입력값과 활동 내용은 시트에 저장한다. 저장·수정·삭제는 명시적인 버튼으로 수행하고 시트가 기준 데이터다. 이 역할 분담을 다시 선택하게 하지 않는다.
- 시트에 보관하지 않는 실시간 상태는 브라우저 SDK로 RTDB에 직접 읽고 쓰며 Apps Script를 중계하지 않는다. Firebase 공개 설정은 스크립트 속성에서 시작·재연결 때 읽도록 AI가 구성한다. 교사에게 전송 경로나 설정 저장소를 다시 고르게 하지 않는다.

### 확인하는 사람이 버튼을 눌러 반영하기

- Firebase 없이 Apps Script와 Google Sheets로 구성한다. 이 선택에 따른 새 Firebase 의존성·설정 탭·인증·Rules 작업은 추가하지 않는다.
- [중복 저장과 동시 수정 처리](data-storage-and-actions.md)는 Firebase 없이 사용하는 앱에도 동일하게 적용한다.
- 학생의 제출·저장 동작으로 데이터를 기록하고, 교사나 다른 학생은 자신의 화면에서 명시적인 조회 버튼을 눌러 최신 내용을 가져오게 한다.
- “Firebase 연결 없이, 학생이 제출한 내용을 시트에 저장하고 선생님이 ‘응답 불러오기’를 눌렀을 때 보여주는 구성으로 진행하겠습니다.”처럼 안내한다.
- 버튼 대신 타이머가 자동으로 조회하도록 만들지 않는다. `setInterval`이나 반복 예약 호출을 통한 폴링도 사용하지 않는다.

### 화면별로 다른 방식을 원하는 경우

“선생님 화면에는 바로 보이고, 학생 화면에서는 버튼으로 확인하면 좋겠어요”처럼 설명하면 그 요구를 그대로 기록한다. 자동 반영이 필요한 화면에는 Firebase를 활용하고 버튼 조회를 원하는 화면은 명시적인 조회 시점에 맞춘다. 사용자가 선택지 중 하나만 다시 고르도록 요구하지 않는다.

입력 동작, 보는 화면, 반영 방식 중 아직 정해지지 않은 핵심 부분만 후속 질문으로 확인한다. 사용자가 Firebase를 사용하지 않겠다는 제약도 명확히 말한 경우에는 그 제약과 원하는 동작을 함께 정리하고 조정할 부분을 확인한다. 명시적인 제약을 무시하고 연결하지 않는다.

## 기획 메모와 중간 요약

기획 메모에는 다음을 기록한다.

- 반영되는 데이터와 이를 바꾸는 사용자 동작
- 데이터를 볼 화면과 공유 범위
- 화면별 자동 반영 또는 버튼 조회 방식
- Firebase 사용 여부와 아직 미정인 사항
- 보관 기록은 시트, RTDB는 실시간 반영용이라는 기본값과 핵심 저장·수정·삭제 버튼의 동작
- Firebase를 선택했다면 관리 도구·로그인·프로젝트·익명 인증·보안 규칙의 준비·배포 상태와 다음에 필요한 조치. 실제 동작 검증은 사용자 점검 결과로 구분한다.

중간 요약은 사용자에게 의미 있는 화면 동작을 먼저 쓰고 Firebase 사용 여부를 함께 표시한다. 예:

> **반영 방식:** 학생이 답안을 제출하면 선생님 화면에 자동 반영 — Firebase 연동

또는:

> **반영 방식:** 학생이 응답을 제출하면 시트에 저장하고, 선생님이 ‘응답 불러오기’를 눌러 확인 — Firebase 미사용

학생 화면에 다른 학생의 응답을 표시하지 않기로 했다면 자동 반영을 선택해도 그 화면 구성은 유지한다. 이는 Firebase 데이터 자체의 읽기 제한과는 구분한다. 현재 기본값에서는 필요한 활동 데이터는 익명 인증 사용자가 읽을 수 있고, 교사 비밀번호는 화면 진입용이며 Firebase 교사 권한을 발급하지 않는다. 학생 기록의 수정·삭제는 소유권 규칙으로 제한한다. 사용자가 반영 방식을 바꾸면 구현 방향과 이후 설정 질문도 함께 갱신하며, 요약에서는 결정된 계획과 실제 연결·구현 완료 상태를 구분한다.

연결 준비를 진행 중이라면 “Firebase 관리 도구 확인 완료 · 로그인 필요” 또는 “계정 연결 확인 완료 · 새 프로젝트 사용은 기본 적용 · 생성 예정”처럼 확인된 상태와 계획을 구분해 덧붙인다. 버튼으로 확인하는 경로에는 이 점검이나 연결 요청을 추가하지 않는다.
