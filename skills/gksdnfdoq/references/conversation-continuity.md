# 질문 대응·진행 기록·재개와 중단

도구 개발 대화를 시작하거나 재개할 때 읽고, 기획·구현·빌드·배포·사용자 피드백의 모든 단계에 적용한다. 사용자가 잠깐 다른 질문을 해도 개발 목표와 돌아올 위치를 보존한다. 스킬 자체를 편집하는 요청만으로 가상의 도구 진행 기록을 만들지는 않는다.

## 현재 메시지의 의도 구분

`SKILL.md`의 정확한 교안 요청을 먼저 확인한 뒤, 현재 메시지와 직전 대화의 맥락으로 아래를 구분한다. 물음표나 특정 단어의 포함 여부만으로 판단하지 않는다.

| 사용자 의도 | 처리 |
| --- | --- |
| 인터뷰 질문에 대한 답변·선택 | 결정 사항을 반영하고 기존 인터뷰나 개발을 이어간다. 재개 문구를 추가로 요구하지 않는다. |
| 명확한 기능 추가·수정·실행 요청 | 허용된 개발 범위에서 요청을 진행한다. “버튼을 크게 해줄래?”도 실행 요청이다. |
| 개발 관련 개념·이유·방법 질문 | 현재 앱을 예로 충분히 설명한다. 질문에 대한 설명만 요청받았다면 개발을 재개 대기로 둔다. |
| 개발과 무관한 주제 질문 | 해당 주제에 자연스럽게 답한다. 이를 앱의 새 요구사항·개발 취소로 처리하지 않고 재개 대기로 둔다. |
| 개발 재개 요청 | 진행 기록을 읽고 현재 위치를 요약한 뒤 남은 질문이나 작업을 이어간다. |
| 개발 중단 요청 | 현재 결과와 다음 할 일을 저장하고 개발을 멈춘다. 앱·파일·배포를 삭제하거나 되돌리지 않는다. |

“Firebase가 뭐야? 설명하고 개발도 계속해줘”처럼 질문과 계속 진행 의사가 함께 있으면 먼저 답한 뒤 이어간다. 재개 대기 중 사용자가 마지막 개발 질문에 분명하게 답하거나 수정 작업을 요청한 경우에도 재개 의사로 받아들인다. 반대로 “계속 설명해줘”는 설명을 더 듣겠다는 뜻이므로 개발 재개로 바꾸지 않는다.

사용자가 다른 앱으로 목표를 바꾸면 기존 기록을 보존하고 새 목표와 구분한다. “그만 하자”가 앱 개발이 아니라 방금 설명하던 별도 주제를 가리킨다면 문맥에 맞게 처리한다. 의도가 실제로 모호한 경우에만 짧게 확인한다.

이미 `사용자 요청으로 중단` 상태라면 설명·다른 주제 질문·교안 링크 요청만으로 그 상태를 `재개 대기`나 `개발 진행 중`으로 바꾸지 않는다. 위 표의 재개 대기 전환은 진행 중인 개발에 적용하며, 중단은 사용자가 개발을 다시 진행하겠다는 뜻을 밝힐 때 해제한다.

## 중간 질문에 답한 뒤의 공통 안내

진행하던 개발이 있는 동안 개념 설명이나 다른 주제의 질문에 답한 경우, **두 유형 모두 답변 마지막에 재개·중단 방법을 한 줄로 안내한다.** 정확한 교안 명령을 처리한 경우에도 개발이 진행 중이었다면 동일하게 안내한다.

> 개발을 이어가고 싶으시면 **“다시 진행해보자”**, 여기서 멈추고 싶으시면 **“그만 하자”**라고 말씀해 주세요. 이어갈 때는 지금까지 정한 내용부터 계속할게요.

- 개발 관련 질문에는 현재 앱에서 그 개념이 맡는 역할을 연결해 설명한다. 아직 결정하지 않은 방식을 설명만으로 확정하지 않는다.
- 다른 주제 질문에는 해당 내용을 중심으로 답한다. 답변 뒤에 개발 인터뷰 질문까지 붙이지 않으며, 별도 대화 내용을 앱 기획이나 진행 기록에 넣지 않는다.
- 안내를 생략해 사용자가 어떻게 돌아올지 모르게 하지 않는다. 다만 일반 인터뷰 답변·개발 실행 요청·명시적인 중단 응답마다 이 문구를 반복하지 않는다.
- 질문과 명확한 계속 진행 요청이 함께 있었다면 재개 대기로 묶지 않고 이어갈 위치를 짧게 알린다. 이미 재개를 요청한 사용자에게 재개 문구를 다시 보내라고 하지 않는다.
- 기존 개발이 없는 단독 질문에는 개발로 돌아오라는 안내나 진행 기록 생성을 붙이지 않는다.

## 진행 기록 파일의 위치와 작성 시점

- 앱별 로컬 작업 폴더의 루트에 **`개발진행기록.md`**를 둔다. 기존 파일이 있으면 읽고 해당 앱의 기록인지 확인한 뒤 필요한 부분을 갱신한다. 여러 앱의 기록을 한 파일에 덮어쓰지 않는다.
- 작업 폴더를 정한 뒤 처음 준비할 때 만들고, 주요 기능·디자인 결정, 실행 형태 선택·클론·환경 준비·구현·설정·빌드·패키징·푸시·배포 결과, 질문으로의 전환, 중단과 재개 때 최신화한다. 단순 대화 한 문장마다 전체 기록을 다시 출력하거나 새로운 파일을 만들지는 않는다.
- 만들 도구와 실행 형태를 알아보는 중에도 폴더가 정해졌다면 `현재 단계: 도구와 사용 환경 파악`처럼 현재 상태를 기록할 수 있다. Apps Script 경로로 정한 경우에만 스크립트 ID·클론 상태를 남긴다. 이때 `clasp clone`은 별도 빈 하위 폴더에서 수행하고 작업 폴더와 클론 폴더를 각각 남긴다. 실행 프로그램은 실제 소스 위치·운영체제·빌드 환경을 기록하며 스크립트 ID를 미정 과제로 남기지 않는다. 기존 프로젝트는 재사용한다.
- 앱별 작업 폴더가 아직 없고 개발을 진행할 단계도 아니라면 경로를 임의로 정해 다른 프로젝트에 기록하지 않는다. 필요한 내용은 대화에서 유지하다 폴더가 정해지면 저장한다. 기록 파일을 쓸 수 없는 환경에서는 저장했다고 말하지 않고 복사 가능한 진행 요약과 제한을 알린다.
- 기록은 개발용 로컬 문서다. Apps Script 업로드·웹앱 배포·실행 파일 패키징 등 사용자에게 전달할 제품에서 제외하고, 별도 요청 없이 공개 저장소에 올리지 않는다. 필요한 경우 해당 앱의 업로드 제외 설정과 로컬 Git 제외 설정에 경로를 추가한다. 기존 제외 설정은 보존한다.

## 기록할 내용

정리된 최신 상태를 유지한다. 긴 대화 원문 대신 결정 사항과 실행 결과를 남기며, 미확인 상태를 성공이나 완료로 쓰지 않는다. 기본 형태는 다음과 같다. 해당하지 않는 선택적 항목은 생략한다.

```markdown
# 개발 진행 기록

- 갱신 시각:
- 도구 이름·목적:
- 실행 형태·선택 이유:
- 대상 기기·운영체제·사용 기술:
- 작업 폴더:
- 상태: 개발 진행 중 / 질문 답변 후 재개 대기 / 사용자 요청으로 중단 중 현재 값 하나
- 현재 단계:
- 소스 위치:
- Apps Script 경로인 경우에만 스크립트 ID·클론 폴더:

## 확정 사항
- 사용자·핵심 흐름·기능:
- 화면·로그인·접근 방식:
- 디자인:
- 저장·화면 반영 방식:
- 사용자가 선택한 내용과 기본 적용 사항의 구분:

## 완료한 작업
- 실제로 마친 작업, 관련 파일, 확인된 명령 실행 결과:

## 아직 남은 내용
- 미완료 작업·오류·미정 사항·제안 중인 내용:
- 마지막으로 답변을 기다리던 개발 질문:

## 다음에 이어갈 위치
- 재개 직후 할 질문 또는 작업:
- 필요한 사용자 조치:

## 연결·빌드·배포와 사용자 점검
- Firebase를 선택한 경우 프로젝트·준비 상태:
- 앱 내 AI를 요청한 경우 서비스·키 준비 여부만:
- 실행 프로그램인 경우 빌드·패키징 명령, 확인된 결과와 산출물 경로·대상 OS:
- 웹앱인 경우 실제 접속 URL·배포 결과, Apps Script이면 배포 ID·버전도 기록:
- 해당하는 경우 푸시 결과:
- 사용자 동작 점검 전인지, 사용자가 알려준 결과가 있는지:
```

비밀번호·API KEY·로그인 토큰·학생 명렬이나 개인정보·학생 답안 원문은 기록하지 않는다. 키 설정 완료 여부처럼 상태만 남긴다. 날씨 등 다른 주제의 대화 내용도 남기지 않는다. README는 교사의 앱 사용 설명서로 유지하고, 이 파일에는 개발자가 다시 작업할 현재 위치를 기록한다.

## 재개 절차

1. “다시 진행해보자”, “이어서 하자”, “다시 웹앱 만들자”, “다시 프로그램 만들자”, 문맥상 개발을 가리키는 “계속해줘” 등을 재개 의사로 이해한다. 정확한 특정 문구만 허용하는 명령으로 만들지 않는다.
2. 현재 앱의 `개발진행기록.md`를 읽는다. 새 대화라면 사용자가 연 프로젝트 폴더나 지정한 경로부터 확인한다. 기록이 없거나 앱을 식별할 수 없을 때만 기존 폴더 등 필요한 정보를 확인하며, 기억에 없는 과거 결정을 만들어내지 않는다.
3. 기록의 실행 형태·소스 위치와 실제 파일·설정을 대조한다. Apps Script는 스크립트 ID·클론 위치와 `.clasp.json`을, 실행 프로그램은 프로젝트·빌드 설정·산출물 경로를 확인하는 등 선택한 경로에 필요한 항목만 본다. 기록과 다른 변경이 있으면 실제 확인한 내용으로 갱신한다. 파일·설정 읽기를 이유로 앱 테스트를 실행하거나 빌드·푸시·배포를 무조건 반복하지 않는다.
4. 이미 결정한 내용과 지금 이어갈 단계를 한두 문장으로 알려준다. 처음부터 다시 인터뷰하거나 실행 형태 선택·환경 준비를 반복하지 않는다. Apps Script 경로에서도 이미 받은 스크립트 ID·로그인·클론을 반복하지 않는다. 필요한 권한이나 준비가 실제로 없는 단계만 안내한다.
5. 상태를 `개발 진행 중`으로 갱신하고 남아 있던 질문이나 작업부터 이어간다. 마지막 질문에 이미 새 답변을 받았다면 그것을 반영해 다음 단계로 간다.

예: “학생·교사 화면 분리와 로그인 방식까지 정했습니다. 다음은 학생 응답을 다른 화면에 반영하는 방식을 정할 차례예요.”

## 중단 절차

- 사용자가 개발을 “그만 하자”, “개발은 멈추자”, “오늘은 여기까지”라고 하면 완료·미완료 작업과 재개할 위치를 저장하고 상태를 `사용자 요청으로 중단`으로 바꾼다. 상태 저장 외의 새 개발·빌드·패키징·푸시·배포 명령은 시작하지 않는다.
- 질문 답변 후 재개 대기나 사용자 중단 요청이 도착했을 때 이미 실행 중이던 명령이 있다면 실제 확인된 결과와 미확인 부분을 구분해 기록한다. 시작만 한 작업을 완료로 쓰거나 같은 변경을 중복 실행하지 않는다.
- “현재 내용과 다음 할 일을 저장하고 멈췄습니다. 나중에 ‘다시 진행해보자’라고 말씀하시면 이어갈게요.”처럼 짧게 알린다. 실제 기록 파일을 쓰지 못했다면 그 사실을 반영한다.
- 중단은 완료나 삭제가 아니다. 사용자가 나중에 명시적으로 재개하면 저장해 둔 위치에서 이어간다.
