# gksdnfdoq: 교사용 웹앱·실행 프로그램 제작 스킬

프로그래밍을 몰라도 Codex와 대화하면서 수업·업무용 웹앱, 컴퓨터에서 실행하는 프로그램 등 필요한 도구를 만드는 스킬입니다. 만들고 싶은 것이 막연해도 괜찮습니다. AI가 예시를 들어 질문하고, 지금까지 정한 내용을 요약하며, 먼저 사용할 수 있는 첫 버전을 만든 뒤 피드백으로 보완합니다.

**처음 한 번 설치 → 만들고 싶은 도구 설명 → 제작 방식에 맞는 준비 → 대화로 제작 → 접속 링크나 실행 파일로 직접 확인**하는 순서입니다.

이 저장소에는 AI가 따를 제작 지침이 들어 있습니다. 설치만으로 완성된 도구가 생기지는 않습니다. 원하는 기능과 사용 환경에 따라 제작 방식을 정하며, **Google Apps Script 웹앱으로 만들 때만 Google 계정·시트·스크립트 ID를 준비합니다.**

저장소는 **`vkfks8524-pixel/gksdnfdoq`**, 설치할 스킬 폴더는 **`skills/gksdnfdoq`**, 설치 후 사용할 스킬 이름은 **`gksdnfdoq`**입니다.

처음 요청할 때 이미 원하는 도구를 설명했다면 같은 질문을 반복하지 않고 필요한 부분부터 이어갑니다.

## 3. 제작 방식에 맞게 준비하기

AI가 원하는 기능과 사용 환경을 바탕으로 제작 방식을 정하고 쉽게 설명합니다. 선생님이 기술 이름을 먼저 골라야 하는 것은 아닙니다. “수업용”이나 “업무용”이라는 분류만으로 제작 방식을 확정하지 않습니다.

| 만들 도구 | 이어지는 준비 |
| --- | --- |
| Google 시트에 기록을 모으는 Apps Script 웹앱 | 스크립트 ID를 요청하고 기존 프로젝트를 가져옵니다. 아래 준비 방법을 따르세요. |
| Windows 실행 파일, 다른 프로그램 위에 떠 있는 펫 등 | 필요한 운영체제·사용 방식과 제작 환경을 확인하고 프로그램을 구현·빌드합니다. 스크립트 ID는 요청하지 않습니다. |
| Apps Script 이외의 웹앱이나 다른 도구 | 요구에 맞는 기술과 제작 환경을 준비합니다. 스크립트 ID·Google 시트·Firebase를 필수로 요구하지 않습니다. |

예를 들어 “다른 Windows 프로그램 위에 떠 있는 펫”은 브라우저 안에만 그리는 화면으로 대신하지 않고, 다른 창 위에 표시되는 실행 프로그램으로 진행합니다. 반대로 웹에서도 가능한 기능을 무조건 실행 프로그램으로 만들지는 않습니다. 사용 모습이 불분명할 때만 필요한 질문을 합니다.

### Apps Script 웹앱으로 정한 경우: 스크립트 ID 준비

**이 절은 Apps Script 웹앱을 만들 때만 필요합니다.** 실행 프로그램이라면 건너뛰세요.

1. 웹앱의 기록을 저장할 Google 스프레드시트를 새로 만들거나 사용할 시트를 엽니다.
2. 시트 위쪽 메뉴에서 **확장 프로그램 → Apps Script**를 선택합니다.
3. Apps Script 편집기에서 **프로젝트 설정(톱니바퀴)**을 엽니다.
4. **ID → 스크립트 ID**를 복사합니다.
5. Codex가 요청하면 복사한 ID를 전달합니다.

스프레드시트 주소에 있는 ID나 배포된 웹앱 주소가 아니라 **스크립트 ID**입니다. 반드시 사용할 시트의 메뉴에서 Apps Script를 열어주세요. 이 연결을 이용해 AI가 시트를 자동으로 찾습니다.

AI는 `clasp`라는 Google Apps Script 관리 도구로 해당 프로젝트 파일을 작업 폴더에 가져옵니다. 처음 사용하는 컴퓨터에서는 도구 설치, Google 로그인, Apps Script API 사용 설정 등이 필요할 수 있습니다. AI가 실제 환경을 확인하고 필요한 단계만 안내합니다. 로그인과 계정 권한 승인은 선생님이 진행합니다. 비밀번호나 로그인 토큰을 채팅에 붙여 넣지는 마세요.

## 4. 어떤 대화를 하게 되나요?

처음부터 만들고 싶은 도구와 사용 상황을 이야기합니다. 막연하면 수업용인지 업무용인지 그 밖의 용도인지부터 좁혀갑니다. Apps Script 프로젝트를 가져온 뒤에도 앞서 설명한 내용은 유지하므로 같은 이야기를 반복할 필요가 없습니다.

예를 들어 다음처럼 답할 수 있습니다.

> 수업에서 학생들이 짧은 생각을 제출하고, 제가 학급별로 모아 보고 싶어요.

> 행사 신청을 받고 싶어요. 구체적인 화면은 아직 잘 모르겠어요.

> 학생들이 문제를 풀고 결과를 확인하는 앱을 만들고 싶어요.

> 다른 프로그램을 쓰는 동안에도 화면 위에 떠 있는 Windows 펫 프로그램을 만들고 싶어요.

> 제 컴퓨터에서 폴더를 골라 파일 이름을 정리하는 실행 프로그램을 만들고 싶어요.

AI는 한 번에 1~2개 정도의 질문을 하고, 선택지를 제시할 때에도 자유롭게 설명할 수 있다고 안내합니다. 목적·실행 형태·사용자·화면·주요 기능·디자인이 정해질 때마다 요약해 보여줍니다. 마음과 다르게 정리된 부분은 바로 고쳐주세요.

첫 버전을 만들 정보가 모이면 제작을 시작합니다. 모든 기능을 미리 확정하지 않아도 됩니다. 결과물을 사용해본 뒤 “글씨를 키워줘”, “학생별로 다시 보고 싶어”, “제출 후 수정 버튼도 필요해”처럼 요청하며 완성합니다.

### 중간에 다른 질문을 해도 괜찮아요

개발 도중 “Firebase가 뭐예요?”처럼 개발과 관련된 질문을 하면 현재 만드는 앱을 예로 설명합니다. “오늘 날씨는 어때요?”처럼 다른 주제로 질문하면 그 질문에 답하고, 만들던 앱의 목표와 결정 사항을 유지합니다. 두 경우 모두 답변 끝에 다음 안내를 덧붙입니다.

> 개발을 이어가고 싶으시면 **“다시 진행해보자”**, 여기서 멈추고 싶으시면 **“그만 하자”**라고 말씀해 주세요. 이어갈 때는 지금까지 정한 내용부터 계속할게요.

질문에 대한 설명만 요청했다면 답변 후 개발을 재개 대기로 둡니다. “다시 진행해보자”, “이어서 하자”, “다시 웹앱 만들자”, “다시 프로그램 만들자”라고 하면 돌아옵니다. 일반 인터뷰 질문에 답하거나 수정할 내용을 요청할 때에는 이 문구를 매번 붙일 필요가 없습니다. “설명하고 개발도 계속해줘”처럼 함께 요청하면 설명한 뒤 이어갑니다.

작업 폴더에는 **`개발진행기록.md`**를 남깁니다. 만들 도구와 실행 형태·운영체제·확정 사항, 현재 단계, 완료·미완료 작업, 답변을 기다리던 질문, 다음 할 일과 실제 빌드·배포 결과를 기록합니다. 스크립트 ID는 Apps Script 경로에서만 남깁니다. 비밀번호·API KEY·학생 개인정보와 다른 주제의 대화 내용은 기록하지 않습니다. 이 파일은 개발을 다시 이어가기 위한 로컬 기록이며, 웹앱이나 실행 파일에 포함해 배포하지 않습니다.

“그만 하자”라고 하면 현재 내용과 다음 할 일을 저장하고 개발을 멈춥니다. 나중에 다시 이어갈 수 있으며, 만들어둔 앱과 자료를 삭제하지 않습니다.

### 교안 링크 보기

Codex에 아래 문장만 보내면 지정된 교안 링크를 안내합니다.

```text
교안 보여줘
```

`교안보여줘`나 `  교안   보여줘  `처럼 공백만 다른 입력도 가능합니다. **메시지 전체에서 공백을 제외한 글자가 정확히 `교안보여줘`여야 합니다.** `교안`, `내 교안 보여줘`, `교안 보여주세요`, `교안 보여줘!`처럼 다른 글자나 문장부호가 있으면 이 단축 명령으로 처리하지 않습니다. 문장 속에 해당 표현이 들어간 것만으로도 실행되지 않습니다.

개발 중이었다면 링크와 함께 재개·중단 방법을 안내합니다. 개발을 시작하지 않은 상태에서는 도구 인터뷰나 스크립트 ID 요청 없이 링크만 제공합니다. 교안 요청은 Codex 대화에서 사용하는 안내이며, 제작 중인 도구에 교안 기능을 자동으로 추가하지 않습니다.

### 만들 도구 안의 AI 기능을 요청한 경우

AI 활용 여부를 먼저 질문하지는 않습니다. 선생님이 대화 중 “앱에서 AI가 학생 글에 피드백해주면 좋겠어요”처럼 AI 기능을 원한다고 말하면, 그때 API가 무엇인지와 API KEY가 왜 필요한지를 실제 앱의 흐름에 맞춰 친절하고 상세하게 설명합니다.

API는 앱이 AI 서비스에 일을 요청하고 결과를 받는 연결 창구이고, 이 스킬의 기본적인 외부 AI API 연결 방식에는 해당 서비스의 API KEY가 필요합니다. 설명을 들은 뒤 사용할 수 있는 키가 있는지와 어느 서비스의 키인지 확인합니다. 키가 없거나 잘 모르겠어도 현재 상황에 맞춰 준비 방법을 안내받을 수 있습니다. **키 문자열을 채팅에 보내지는 마세요.** 실제 연결 단계에서 제작 환경에 맞는 안전한 설정 위치를 안내합니다. 웹앱의 공용 키는 서버 측에 보관하고, 배포할 실행 프로그램에 개발자의 비밀 키를 넣지는 않습니다. 개인 프로그램에서 자신의 키를 쓰는 경우에는 적절한 로컬 비밀 설정 방법을 안내합니다. 로컬 AI 등 다른 방식을 지정했다면 그 방식에 맞게 준비합니다.

Codex에게 앱 개발을 맡기는 것과 완성된 도구 안에 AI 기능을 넣는 것은 별개입니다. 앱 안의 AI 기능을 요청하지 않았다면 이 API 설명·키 확인 절차를 추가하지 않습니다.

## 5. 기본으로 적용되는 방식

### 모든 제작 방식에 공통으로 적용

- 원하는 기능과 디자인을 대화로 정하고, 핵심 기능이 정리되면 첫 버전을 만든 뒤 피드백으로 보완합니다.
- 요청하지 않은 이모지는 사용하지 않습니다. 정돈된 선 아이콘과 도형, 디자인에 맞는 알림과 작업 중 표시를 사용합니다.
- 도구마다 비전공자도 따라 할 수 있는 한국어 README를 작성하고 코드나 기능 변경 때 함께 갱신합니다.
- 진행 기록을 남겨 중간에 질문하거나 멈춰도 이어갈 수 있게 합니다.
- AI는 코드 작성과 필요한 빌드·배포를 수행합니다. 실제 사용 점검은 선생님이 하고, AI는 맞춤 체크리스트를 제공합니다.

### 실행 프로그램의 제작과 전달

운영체제와 필요한 동작에 맞춰 프로그램을 구현하고, 가능한 제작 환경에서 실행 파일·설치 파일 또는 필요한 파일을 묶은 폴더를 만듭니다. 코드나 빌드 명령만 보여주는 것으로 실행 파일 제작을 완료했다고 안내하지 않습니다. 현재 환경에서 해당 운영체제용 파일을 만들 수 없다면 준비된 소스·빌드 방법과 아직 필요한 작업을 구분해서 안내합니다.

README에는 **어떤 파일을 열어야 하는지, 설치가 필요한지, 조작·종료 방법, 자료 저장 위치, 업데이트 방법**을 적습니다. 함께 있어야 하는 파일이 있으면 그 폴더 전체를 보관하도록 안내합니다. 파일을 처리하는 프로그램은 기존 자료를 보존하도록 설계합니다.

실행 프로그램이라는 이유만으로 Google 로그인·명렬·시트 저장·Firebase 연결을 추가하지 않습니다. 해당 기능이 필요하다고 정한 경우에만 연결합니다.

### Apps Script 웹앱에만 적용되는 기본값

**아래 표와 학생 명렬·교사 비밀번호·실시간 반영 설명은 Apps Script 웹앱으로 정한 경우에 적용합니다.**

| 항목 | 기본 동작 |
| --- | --- |
| 저장 | 보관할 최종 입력값·답안·활동 기록은 연결된 Google 시트에 저장합니다. |
| 저장·수정·삭제 | 명시적인 버튼으로 처리하고, 중복 저장과 동시 수정 충돌을 다룹니다. |
| 시트 준비 | 웹앱이 열릴 때 필요한 탭과 헤더가 없으면 만들고, 기존 자료는 보존합니다. |
| 학생 화면 | 수업용 앱에서 교사·학생 화면을 분리하면 학번·이름 로그인으로 시작합니다. |
| 교사 화면 | 같은 조건에서 학년·반 선택으로 시작하며, 접속 주소를 학생 화면과 나눕니다. |
| 디자인 | 대화로 정합니다. 사용자가 요청하지 않으면 이모지를 사용하지 않고, 정돈된 SVG 선 아이콘·기하학적 도형을 활용합니다. 앱 디자인에 맞는 알림창과 작업 중 표시를 제공합니다. |
| 배포 | 기존 배포가 있으면 같은 주소를 유지하면서 새 버전으로 갱신합니다. |
| 설명서 | 각 웹앱에 상세한 한국어 README를 작성하고 코드나 기능 변경 때 함께 갱신합니다. |
| 점검 | AI는 앱 동작 테스트를 실행하지 않고, 선생님이 확인할 체크리스트를 제공합니다. |

### 학생 명렬 준비

수업용 앱에서 교사·학생 화면을 분리하는 경우, 연결된 시트의 **`명렬` 탭**을 사용합니다.

| 위치 | 입력할 내용 |
| --- | --- |
| A1 | 학번 |
| B1 | 이름 |
| A2부터 아래 | 학생의 5자리 학번 |
| B2부터 아래 | 같은 행에 해당 학생의 이름 |

예를 들어 학번 `10101`은 **1학년 1반 1번**입니다. 학생이 입력한 학번과 이름이 같은 행의 값과 모두 일치해야 로그인됩니다. 교사 화면의 학년·반 목록도 이 학번들로 만듭니다. AI가 실제 학생 명단을 임의로 채워 넣지는 않습니다.

### 교사 화면 비밀번호

기본값은 교사용 주소를 열면 바로 들어가는 방식입니다. 대화에서 비밀번호 화면을 선택하면 **`설정` 탭 A1 셀**에 선생님이 정한 비밀번호를 입력합니다. A1은 비밀번호 값이 들어가는 칸이며 헤더를 쓰지 않습니다. 비어 있으면 통과되지 않습니다.

이 비밀번호는 **교사 화면 진입용**입니다. Firebase 활동 데이터의 읽기 권한을 제한하는 비밀번호가 아니며, 별도의 Firebase 교사 권한을 발급하지 않습니다. Firebase를 쓰는 경우 필요한 실시간 활동 데이터는 익명 인증된 이용자가 읽을 수 있도록 구성하되, 다른 학생의 기록을 임의로 수정·삭제하지 못하는 소유권 규칙은 유지합니다. 데이터 자체를 특정 교사에게만 공개해야 한다면 그 요구를 인터뷰에서 따로 알려주세요.

### 실시간 반영이 필요할 때

AI는 앱의 실제 사용 장면에 맞춰 두 방식을 설명하고 질문합니다.

- **다른 화면에 바로 반영:** Firebase 연결이 필요합니다. AI가 연결 상태를 확인하고, 새 앱 전용 프로젝트·익명 인증·Realtime Database·규칙 설정을 진행합니다. 계정 로그인이나 권한 승인이 필요한 단계는 안내받습니다.
- **버튼을 눌러 새 기록 확인:** Firebase 없이 Google Apps Script와 시트로 진행할 수 있습니다.

Firebase를 사용해도 최종 보관 자료는 시트에 저장합니다. Firebase Realtime Database는 실시간 화면 반영용 상태를 다룹니다. 시트에 보관하지 않는 상태는 브라우저와 Firebase가 직접 주고받습니다. 시트 저장·수정·삭제는 버튼에서 처리합니다.

공개 Firebase 연결 설정은 별도 스크립트 속성에서 실행 시 읽습니다. 이 구조가 배포된 뒤에는 연결 설정값만 바꾸는 경우 코드 수정·재배포 없이 다음 연결부터 적용됩니다. 다른 프로젝트로 바꾸면 그 프로젝트의 인증·규칙 등은 별도로 준비해야 합니다.

## 6. 완성된 첫 버전 확인하기

Apps Script 웹앱은 실제 접속 링크를 제공합니다. 화면을 나눈 경우 교사용·학생용 등 화면별 링크가 따로 나오며, 이후 수정할 때에도 기존 배포 주소를 유지합니다. 다른 방식의 웹앱은 정한 배포 방식에 맞는 실제 접속 경로를 안내합니다.

실행 프로그램은 생성된 실행 파일·설치 파일 또는 배포 폴더의 위치와 여는 방법을 제공합니다. 예를 들어 Windows 펫이라면 파일 실행, 다른 창 위 표시, 이동·숨기기·종료를 확인할 수 있도록 안내합니다. 실제로 만들지 않은 파일이나 공개하지 않은 다운로드 주소를 제공하지 않습니다.

함께 받은 체크리스트에 따라 직접 확인하세요. 다음은 Apps Script 수업용 웹앱의 예시이며, 실제 목록은 도구 기능에 맞춰 제공됩니다.

- 학생이 명렬의 학번·이름으로 로그인되는지
- 교사 화면에서 학년·반이 올바르게 표시되는지
- 저장 버튼을 누른 값이 시트에 기록되는지
- 중복 클릭이나 수정·삭제 시 기대한 결과가 나오는지
- 선택한 방식대로 다른 화면에 반영되는지
- 알림창과 작업 중 표시가 적절하게 나오는지
- 기존 시트 자료가 유지되는지

실행 프로그램에서는 다음과 같은 항목을 확인합니다.

- 안내한 운영체제에서 실행 파일을 열 수 있는지
- 필요한 기능과 창 표시·이동·종료가 의도대로 동작하는지
- 파일을 처리한다면 원본이 보존되고 결과가 안내된 위치에 생기는지
- 오류 안내와 작업 중 표시가 이해하기 쉬운지
- 프로그램을 다시 열거나 업데이트해도 보관할 자료가 유지되는지

수정 요청에는 **어느 화면에서 → 무엇을 눌렀을 때 → 어떤 결과가 나왔는지 → 어떻게 되길 원하는지**를 적어주면 도움이 됩니다. AI가 빌드·배포를 완료했다는 안내는 실제 실행과 동작 점검까지 끝났다는 뜻은 아닙니다. 실행 파일을 직접 열어보는 작업도 선생님이 합니다.
