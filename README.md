# 교사용 Google Apps Script 웹앱 제작 스킬

프로그래밍을 몰라도 Codex와 대화하면서 수업·업무용 웹앱을 만드는 스킬입니다. 만들고 싶은 것이 막연해도 괜찮습니다. AI가 예시를 들어 질문하고, 지금까지 정한 내용을 요약하며, 먼저 사용할 수 있는 첫 버전을 만든 뒤 피드백으로 보완합니다.

**처음 한 번 설치 → 스킬 실행 → 스크립트 ID 전달 → 대화로 제작 → 배포된 링크에서 직접 확인**하는 순서입니다.

이 저장소에는 AI가 따를 제작 지침이 들어 있습니다. 설치만으로 완성된 웹앱이 생기지는 않으며, 각 선생님의 Google 계정과 시트를 연결해 앱을 만듭니다.

## 1. 가장 간단한 설치 방법

파일 작업과 명령 실행이 가능한 Codex 앱·CLI·IDE 환경에서 사용하세요. 컴퓨터에 웹앱 작업용 빈 폴더를 하나 만들고, Codex에서 그 폴더를 작업 공간으로 선택합니다.

다음 내용을 **Codex 채팅에 그대로 복사해서 보내세요.** 선생님이 Git 명령을 입력하거나 ZIP 파일을 직접 내려받을 필요는 없습니다.

```text
$skill-installer
다음 GitHub 스킬을 이 컴퓨터에서 사용할 수 있도록 설치해줘.
https://github.com/vkfks8524-pixel/teacher-gas-webapp-skill/tree/main/skills/teacher-gas-webapp
```

Codex가 설치 완료를 알려주면 다음 메시지에서 실행할 수 있습니다. 스킬이 보이지 않으면 Codex를 다시 시작한 뒤 시도하세요. 네트워크 접근이나 설치 폴더 접근에 대한 승인이 표시되면 요청 내용을 확인하고 진행합니다.

GitHub 링크를 웹브라우저에서 열기만 하면 자동 설치되는 것은 아닙니다. **링크를 Codex에 전달해 설치를 요청하는 것**이 핵심입니다. 공개 저장소를 내려받는 데 선생님 개인의 GitHub 저장소를 만들 필요는 없습니다.

설치 기능과 스킬 인식 방식은 [OpenAI 공식 스킬 안내](https://learn.chatgpt.com/docs/build-skills)를 참고하세요. Codex의 설치 도구가 해당 환경에 맞는 설치 위치를 선택하도록 두면 됩니다.

## 2. 스킬 실행하기

설치가 끝나면 다음 문장을 보내세요.

```text
$teacher-gas-webapp
웹앱을 만들고 싶어요. 스크립트 ID 확인과 프로젝트 준비부터 시작해줘.
```

`$`로 선택하는 메뉴가 보이지 않으면 “설치한 teacher-gas-webapp 스킬을 사용해 웹앱 제작을 시작해줘”라고 요청해도 됩니다.

AI는 먼저 **스크립트 ID**를 요청합니다. 이때 기능을 모두 정해둘 필요는 없습니다.

## 3. 스크립트 ID 준비하기

1. 웹앱의 기록을 저장할 Google 스프레드시트를 새로 만들거나 사용할 시트를 엽니다.
2. 시트 위쪽 메뉴에서 **확장 프로그램 → Apps Script**를 선택합니다.
3. Apps Script 편집기에서 **프로젝트 설정(톱니바퀴)**을 엽니다.
4. **ID → 스크립트 ID**를 복사합니다.
5. Codex가 요청하면 복사한 ID를 전달합니다.

스프레드시트 주소에 있는 ID나 배포된 웹앱 주소가 아니라 **스크립트 ID**입니다. 반드시 사용할 시트의 메뉴에서 Apps Script를 열어주세요. 이 연결을 이용해 AI가 시트를 자동으로 찾습니다.

AI는 `clasp`라는 Google Apps Script 관리 도구로 해당 프로젝트 파일을 작업 폴더에 가져옵니다. 처음 사용하는 컴퓨터에서는 도구 설치, Google 로그인, Apps Script API 사용 설정 등이 필요할 수 있습니다. AI가 실제 환경을 확인하고 필요한 단계만 안내합니다. 로그인과 계정 권한 승인은 선생님이 진행합니다. 비밀번호나 로그인 토큰을 채팅에 붙여 넣지는 마세요.

## 4. 어떤 대화를 하게 되나요?

프로젝트를 가져온 다음, 수업용인지 업무용인지 그 밖의 용도인지부터 대화를 시작합니다. 이미 구상이 있으면 바로 설명해도 됩니다.

예를 들어 다음처럼 답할 수 있습니다.

> 수업에서 학생들이 짧은 생각을 제출하고, 제가 학급별로 모아 보고 싶어요.

> 행사 신청을 받고 싶어요. 구체적인 화면은 아직 잘 모르겠어요.

> 학생들이 문제를 풀고 결과를 확인하는 앱을 만들고 싶어요.

AI는 한 번에 1~2개 정도의 질문을 하고, 선택지를 제시할 때에도 자유롭게 설명할 수 있다고 안내합니다. 목적·사용자·화면·주요 기능·디자인이 정해질 때마다 요약해 보여줍니다. 마음과 다르게 정리된 부분은 바로 고쳐주세요.

첫 버전을 만들 정보가 모이면 제작을 시작합니다. 모든 기능을 미리 확정하지 않아도 됩니다. 결과물을 사용해본 뒤 “글씨를 키워줘”, “학생별로 다시 보고 싶어”, “제출 후 수정 버튼도 필요해”처럼 요청하며 완성합니다.

## 5. 기본으로 적용되는 방식

| 항목 | 기본 동작 |
| --- | --- |
| 저장 | 보관할 최종 입력값·답안·활동 기록은 연결된 Google 시트에 저장합니다. |
| 저장·수정·삭제 | 명시적인 버튼으로 처리하고, 중복 저장과 동시 수정 충돌을 다룹니다. |
| 시트 준비 | 웹앱이 열릴 때 필요한 탭과 헤더가 없으면 만들고, 기존 자료는 보존합니다. |
| 학생 화면 | 수업용 앱에서 교사·학생 화면을 분리하면 학번·이름 로그인으로 시작합니다. |
| 교사 화면 | 같은 조건에서 학년·반 선택으로 시작하며, 접속 주소를 학생 화면과 나눕니다. |
| 디자인 | 대화로 정합니다. 앱 디자인에 맞는 알림창과 작업 중 표시를 제공합니다. |
| 배포 | 기존 배포가 있으면 같은 주소를 유지하면서 새 버전으로 갱신합니다. |
| 설명서 | 각 웹앱에 상세한 한국어 README를 작성하고 코드나 기능 변경 때 함께 갱신합니다. |
| 점검 | AI는 앱 동작 테스트를 실행하지 않고, 선생님이 확인할 체크리스트를 제공합니다. |

### 학생 명렬 준비

수업용 앱에서 교사·학생 화면을 분리하는 경우, 연결된 시트의 **`명렬` 탭**을 사용합니다.

| 위치 | 입력할 내용 |
| --- | --- |
| A1 | 학번 |
| B1 | 이름 |
| A2부터 아래 | 학생의 5자리 학번 |
| B2부터 아래 | 같은 행에 해당 학생의 이름 |

예를 들어 학번 `10101`은 **1학년 1반 1번**입니다. 학생이 입력한 학번과 이름이 같은 행의 값과 모두 일치해야 로그인됩니다. 교사 화면의 학년·반 목록도 이 학번들로 만듭니다. AI가 실제 학생 명단을 임의로 채워 넣지는 않습니다.

### 교사 화면 비밀번호

기본값은 교사용 주소를 열면 바로 들어가는 방식입니다. 대화에서 비밀번호 화면을 선택하면 **`설정` 탭 A1 셀**에 선생님이 정한 비밀번호를 입력합니다. A1은 비밀번호 값이 들어가는 칸이며 헤더를 쓰지 않습니다. 비어 있으면 통과되지 않습니다.

이 비밀번호는 **교사 화면 진입용**입니다. Firebase 활동 데이터의 읽기 권한을 제한하는 비밀번호가 아니며, 별도의 Firebase 교사 권한을 발급하지 않습니다. Firebase를 쓰는 경우 필요한 실시간 활동 데이터는 익명 인증된 이용자가 읽을 수 있도록 구성하되, 다른 학생의 기록을 임의로 수정·삭제하지 못하는 소유권 규칙은 유지합니다. 데이터 자체를 특정 교사에게만 공개해야 한다면 그 요구를 인터뷰에서 따로 알려주세요.

### 실시간 반영이 필요할 때

AI는 앱의 실제 사용 장면에 맞춰 두 방식을 설명하고 질문합니다.

- **다른 화면에 바로 반영:** Firebase 연결이 필요합니다. AI가 연결 상태를 확인하고, 새 앱 전용 프로젝트·익명 인증·Realtime Database·규칙 설정을 진행합니다. 계정 로그인이나 권한 승인이 필요한 단계는 안내받습니다.
- **버튼을 눌러 새 기록 확인:** Firebase 없이 Google Apps Script와 시트로 진행할 수 있습니다.

Firebase를 사용해도 최종 보관 자료는 시트에 저장합니다. Firebase Realtime Database는 실시간 화면 반영용 상태를 다룹니다. 시트에 보관하지 않는 상태는 브라우저와 Firebase가 직접 주고받습니다. 시트 저장·수정·삭제는 버튼에서 처리합니다.

공개 Firebase 연결 설정은 별도 스크립트 속성에서 실행 시 읽습니다. 이 구조가 배포된 뒤에는 연결 설정값만 바꾸는 경우 코드 수정·재배포 없이 다음 연결부터 적용됩니다. 다른 프로젝트로 바꾸면 그 프로젝트의 인증·규칙 등은 별도로 준비해야 합니다.

## 6. 배포된 웹앱 확인하기

AI는 작업이 끝나면 실제 접속 링크를 제공합니다. 화면을 나눈 경우 교사용·학생용 등 화면별 링크가 따로 나옵니다. 이후 수정할 때에도 기존 배포 주소를 유지합니다.

함께 받은 체크리스트에 따라 직접 확인하세요. 다음은 일반적인 예시이며, 실제 목록은 앱 기능에 맞춰 제공됩니다.

- 학생이 명렬의 학번·이름으로 로그인되는지
- 교사 화면에서 학년·반이 올바르게 표시되는지
- 저장 버튼을 누른 값이 시트에 기록되는지
- 중복 클릭이나 수정·삭제 시 기대한 결과가 나오는지
- 선택한 방식대로 다른 화면에 반영되는지
- 알림창과 작업 중 표시가 적절하게 나오는지
- 기존 시트 자료가 유지되는지

수정 요청에는 **어느 화면에서 → 무엇을 눌렀을 때 → 어떤 결과가 나왔는지 → 어떻게 되길 원하는지**를 적어주면 도움이 됩니다. AI가 배포를 완료했다는 안내는 실제 앱 동작 점검까지 끝났다는 뜻은 아닙니다.

## 7. 이어서 만들기와 스킬 업데이트

같은 앱을 수정할 때에는 기존 작업 폴더와 대화를 이어서 사용하세요. 새 대화에서 시작한다면 이 스킬을 다시 불러오고, 기존 앱 작업 폴더와 스크립트 ID를 알려주세요. 같은 앱에 이미 있는 Firebase 프로젝트와 배포를 재사용합니다.

스킬은 한 번 설치하면 새 앱을 만들 때마다 다시 내려받을 필요가 없습니다. 다만 **GitHub의 변경사항이 설치한 스킬에 자동 반영되지는 않습니다.** 최신 지침을 받고 싶을 때 다음처럼 요청하세요.

```text
설치된 teacher-gas-webapp 스킬을 아래 저장소의 최신 버전과 비교해 업데이트해줘.
내가 수정한 부분이 있으면 먼저 알려주고 기존 사본을 보존해줘.
https://github.com/vkfks8524-pixel/teacher-gas-webapp-skill/tree/main/skills/teacher-gas-webapp
```

스킬 지침을 업데이트하는 것과 이미 만든 웹앱 코드를 수정·재배포하는 것은 별개입니다. 기존 앱에 새 방식을 적용하고 싶으면 해당 앱의 수정도 요청하세요.

## 9. Claude·Google 계열 도구에서도 쓸 수 있나요?

기본 대상은 Codex입니다. 핵심 지침은 일반 Markdown 파일로 작성해 다른 AI 환경에서도 참고할 수 있도록 구성했습니다. 다만 다른 도구의 스킬 설치·호출 방식과 파일·터미널·Google 계정 연결 지원은 별도로 확인해야 합니다. 이 저장소에서는 해당 도구의 자동 설치나 전체 제작 과정을 검증하지 않았습니다.

일반 채팅에 지침만 붙여 넣는 경우 기획 대화에는 활용할 수 있어도, 실제 프로젝트 가져오기·파일 수정·배포까지 자동으로 되는 것은 아닙니다.
